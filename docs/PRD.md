# PRD — 이어 그리기 (한 장 만화)

> 버전 0.1 · 2026-10-07 · 상태: 초안
> 결정 기록: [DECISIONS.md](DECISIONS.md) · 학생 설문과 테스트 원자료는 공개 저장소에 올리지 않는다 (`private/`, git 제외)

## 1. 한 문장 목표

**2~4명이 각자 iPad로 같은 방에 들어가, 만화 한 편을 한 칸씩 차례로 이어 그리고, 마지막에 완성된 이야기를 함께 본다.**

## 2. 배경

### 왜 만드는가

쉬는 시간에 친구에게 "같이 하자"고 말할 수 있는 3~5분짜리 놀이를 만든다. 특히 **혼자 쉬지만 친구가 부르면 함께할 학생들**이 부담 없이 끼어들 수 있는 놀이가 목표다.

### 근거 (요약)

- 학급 설문: 대부분의 학생이 iPad 파티게임에 참여 의향을 보였다. 다만 상당수가 "재미있어 보이면", "친구가 같이 하자고 하면"이라는 조건을 붙였다. 선호하는 한 판 길이는 3~5분이었다.
- 그림을 차례로 이어 그리는 게임을 학생들이 직접 제안했다.
- 후보 활동(A 한 장 이어 그리기, B 만화 돌리기, C 그림 전달) 중 A와 B가 선택되었다. 학생들이 적은 이유: 쉬움, 그리기를 좋아함, 완성된 만화를 함께 보는 재미.
- 국어 교과서의 이어 쓰기, 다음 장면 그리기, 발단-전개-절정-결말 활동과 같은 구조라 학생들에게 익숙하다.
- A′는 이 이유를 모두 담는다: **종이 한 장을 차례로 넘기는 쉬움**, **자기 칸을 온전히 그리는 즐거움**, **완성된 만화를 함께 보는 웃음**.

### 제품 비전 (MVP 범위 밖)

이어 그리기는 앞으로 여러 미니게임을 담을 **교실 파티게임 플랫폼의 첫 번째 게임**이다. 두 번째 게임 후보는 이모지 퀴즈다. 단, **두 번째 게임이 생기기 전까지는 공통 엔진이나 플러그인 구조를 만들지 않는다.**

## 3. 대상 사용자

- 5학년 학생. 학교 iPad와 Safari를 사용한다.
- **설계 기준은 3명이 함께 하는 한 판**이다. 2~4명을 지원한다.
- 친구가 불러야 들어오는 학생을 위해 **들어오기 쉽고, 실수해도 창피하지 않고, 말을 많이 하지 않아도 함께할 수 있어야** 한다.

## 4. 게임 규칙

| 항목 | 규칙 |
|---|---|
| 인원 | 2~4명 |
| 진행 | 한 명씩 차례로 **다음 장면 한 칸**을 그린다 |
| 칸 구성 | 2명: 발단·전개·절정·결말 4칸 (각자 2번)<br>3명: 처음·가운데·끝 3칸<br>4명: 발단·전개·절정·결말 4칸 |
| 칸당 시간 | 기본 **45초**. 방장이 30·45·60초 중 선택. 일찍 끝나면 [완료] |
| 주제 | 시작할 때 이야기 카드 한 장을 무작위로 뽑아 모두에게 보여 준다. 방장은 한 번 다시 뽑을 수 있다 |
| 내 차례 | 앞 칸들을 보고 내 칸을 그린다 |
| 남의 차례 | 그리는 과정을 **실시간으로 구경**만 한다 |
| 결과 | 만화 전체를 한 칸씩 차례로 공개한 뒤 한 화면에 모아 보여 준다 |
| 점수·승패·투표 | 없음 |
| 다시 하기 | 같은 방, 같은 사람으로 새 주제. **첫 순서가 한 칸씩 돌아간다** |

예상 소요 시간: 3명 × 45초 ≈ 2분 15초, 공개 약 1분 → **한 판 약 3~4분**

## 5. 화면과 흐름

```text
홈
 ├ [방 만들기] → 번호 입력 → 대기실 (방장)
 └ [방 들어가기] → 방 코드 + 번호 입력 → 대기실
대기실: 들어온 친구 번호 목록, 방 코드 크게 표시, 칸당 시간 선택(방장)
 ↓ 방장 [시작] (2명 이상)
주제 공개 (3초): "냉장고에서 나온 외계인"
 ↓
차례 진행 × 칸 수
  내 차례: 단계 이름 + 타이머 + 그림판 + 도구 + [완료]
  남의 차례: 실시간 그림 + "13번이 그리는 중" + 타이머
  다음 차례 5초 전: "다음은 너야!"
 ↓
공개: 칸이 하나씩 나타남 (단계 이름, 그린 사람 번호) → 전체 보기
 ↓
[한 판 더] (방장) / [나가기]
```

### 화면별 요구사항

**홈 · 입장**
- 방 코드는 **숫자 4자리**다. 말로 전하기 쉽다.
- 출석번호(1~30)만 입력한다. 이름은 받지 않는다.
- 같은 방에서 이미 쓰이는 번호면 입장을 막고 "이미 들어온 번호예요"라고 안내한다. 단, 그 자리가 **20초 이상 연결이 없으면 새 기기가 자리를 이어받는다**. 기기를 바꾸거나 저장된 정보가 지워진 학생이 빈 자리 때문에 못 들어오는 일을 막기 위해서다 (이전 프로젝트의 빈 자리 문제).
- 게임이 시작된 방에는 들어갈 수 없다. "지금 게임 중이에요. 다음 판에 들어오세요"라고 안내한다.
- 한 방에는 최대 4명까지 들어갈 수 있다.

**대기실**
- 방 코드를 화면에서 가장 크게 보여 준다.
- 들어온 순서대로 번호 목록을 보여 준다. 방장 표시와 연결이 끊긴 사람 표시를 한다.
- 방장만 [시작]과 칸당 시간 선택을 할 수 있다.

**그리기 (내 차례)**
- 맨 위: 단계 이름과 짧은 안내. 예: "③ 절정: 가장 큰 사건이 일어나요!"
- 앞 칸들: 바로 앞 칸은 크게, 그 전 칸들은 작게 보여 준다.
- 그림판: 4:3 비율, 손가락과 Apple Pencil 모두 지원
- 도구: 색 6개 (검정, 빨강, 파랑, 초록, 노랑, 갈색), 굵기 2단계, 지우개, 되돌리기
- 타이머 막대와 [완료] 버튼

**구경 (남의 차례)**
- 그리는 사람의 획이 **선을 하나 그을 때마다** 나타난다 (목표 지연 1초 이내).
- 그림판은 볼 수만 있고 만질 수 없다.

**공개**
- 칸이 1초 간격으로 하나씩 나타나고, 마지막에 전체 만화를 보여 준다.
- 각 칸에 단계 이름과 그린 사람 번호를 표시한다.
- 빈 칸(시간 안에 아무것도 그리지 않음)은 "(빈 칸)"으로 표시한다.

**교사 페이지 (`/teacher`)**
- 교사 코드를 입력해야 들어갈 수 있다. 코드는 Convex 환경 변수 `TEACHER_PASSCODE`에만 저장하고, 서버가 확인한다. 저장소에는 넣지 않는다.
- 최근 24시간 안에 끝난 게임 목록을 보여 준다 (날짜·시간, 주제, 참여 번호).
- 만화 전체를 이미지 한 장으로 보여 준다. iPad에서는 길게 눌러 사진에 저장하고, PC에서는 [다운로드]로 PNG를 받는다.
- 통계, 학생 관리 같은 대시보드 기능은 없다.

## 6. 방장과 예외 상황

| 상황 | 처리 |
|---|---|
| 방장 | 방을 만든 학생. 시작, 칸당 시간, 주제 다시 뽑기, 한 판 더를 담당 |
| 방장이 나감 | 가장 먼저 들어온 학생에게 방장이 넘어감 |
| 새로고침, 화면 잠금 후 복귀 | 같은 기기면 자동으로 같은 방, 같은 자리로 돌아옴 |
| 그리던 학생의 연결이 끊김 | 타이머는 계속 흐름. 시간이 끝나면 그때까지 그린 것으로 칸이 확정됨 |
| 60초 이상 연결 없음 | "자리 비움"으로 표시. 그 학생 차례가 되면 빈 칸으로 넘어감 |
| 대기실에서 60초 이상 연결 없음 | 목록에서 제거 |
| 1명만 남음 | 게임을 끝내고 그때까지 그린 칸으로 공개 |
| [완료] 연타 | 한 번만 처리됨 |

## 7. 장난 방지 (기술적 제한)

- 자기 차례에만 그림판이 열린다. 서버도 "지금 차례인 사람의 획인지"를 확인한다.
- 다른 사람의 칸은 수정하거나 지울 수 없다.
- 게임이 시작되면 새로 들어올 수 없다.
- 채팅과 텍스트 입력은 없다. 출석번호 입력만 있다.

## 8. 기술 요구사항

### 구성

| 영역 | 선택 |
|---|---|
| 코드 관리 | GitHub |
| 프론트엔드 | Vite + React + TypeScript |
| 실시간 · DB · 서버 함수 | Convex |
| 배포 | Vercel |
| 그림판 | Canvas 2D + Pointer Events. 별도 그림 라이브러리 없이 시작 |

### 배포 환경

- **개발과 운영을 처음부터 나눈다.** 로컬 `npx convex dev`는 Convex 개발 배포를 쓰고, Vercel Production은 Convex 운영(prod) 배포를 쓴다.
- Vercel 빌드 명령은 `npx convex deploy --cmd 'npm run build'`로 한다. **Convex 함수와 화면이 한 번에 함께 배포**되어, 화면만 바뀌고 서버 함수는 예전 그대로인 문제를 막는다.
- MVP에서는 Vercel Preview 배포를 쓰지 않는다. 운영 데이터와 섞이는 것을 막기 위해서다.
- `convex/_generated/`는 git에 올린다. 새 작업 환경이나 다른 AI 도구에서도 타입이 바로 보이게 하기 위해서다.
- `convex/` 코드는 경로 별칭(`@/...`) 없이 상대 경로로만 import한다. Convex 배포 시 타입 검사 실패를 막기 위해서다.

### 핵심 원칙

- **타이머의 기준은 서버다.** 서버가 `turnEndsAt`(차례 마감 시각)을 저장하고, 시간이 다 되면 예약 실행 기능(`ctx.scheduler`)으로 다음 차례로 넘긴다. 각 기기는 남은 시간을 표시만 한다.
- **그림은 획(stroke) 단위로 저장한다.** 좌표는 그림판 크기에 대한 비율(0~1)로 저장해서 기기 크기가 달라도 똑같이 보이게 한다. 실시간 구경과 공개 화면이 같은 데이터를 쓴다.
- 획 하나를 DB 문서 하나로 저장해 문서 크기 제한(1MB)을 피한다. 너무 가까운 점은 버리고 좌표는 소수점 셋째 자리까지만 남겨 데이터를 줄인다.
- 차례 넘기기와 완료 처리는 **현재 차례 번호를 함께 보내서**, 이미 넘어간 차례에 대한 요청은 무시한다.
- 기기마다 무작위 `sessionId`를 만들어 브라우저 localStorage에 저장한다. 이것으로 재접속하면 같은 자리로 돌아온다.
- 접속 확인(presence)은 10초마다 신호를 보내 `lastSeenAt`을 갱신하는 방식으로 한다.

### 데이터 모델 (초안, 구현 중 바뀔 수 있음)

```text
rooms    code, status(lobby|playing|reveal), hostSessionId, turnSeconds, createdAt
players  roomId, sessionId, number, joinedAt, lastSeenAt
games    roomId, topic, order[sessionId], stages[], currentTurn, turnEndsAt, status
strokes  gameId, turn, sessionId, color, width, points[], createdAt
events   type, roomId, gameId, at, data
```

### iPad Safari 대응

- 그림판에서 스크롤, 확대, 더블탭 확대, 당겨서 새로고침이 일어나지 않게 막는다 (`touch-action: none` 등).
- 가로 화면을 기준으로 디자인한다. 세로 화면에서도 쓸 수 있어야 한다.
- 설치 없이 Safari 주소로 접속한다.

### 기록 (로그)

다음 이벤트를 시각과 함께 저장한다. 교사 대시보드는 만들지 않고, 개발자가 Convex 대시보드에서 직접 확인한다.

`room_created` `player_joined` `game_started` `turn_started` `turn_submitted`(완료/시간 초과 구분) `player_disconnected` `player_reconnected` `game_revealed` `rematch_started` `player_left`

## 9. 개인정보와 보안

- 이름, 계정, 비밀번호를 받지 않는다. 서버에는 출석번호와 무작위 sessionId만 저장한다.
- 방, 그림, 참가자 데이터는 **24시간 뒤 자동 삭제**한다 (Convex cron). 로그에는 그림을 남기지 않는다.
- 그림은 같은 방 밖으로 공유되지 않는다. 학생 화면에는 저장, 내보내기, 갤러리 기능이 없다. 교사만 교사 페이지에서 24시간 안에 내려받을 수 있다.
- 비밀값은 저장소에 넣지 않는다. `.env.local`은 `.gitignore`에 넣는다.
- 외부 분석 도구나 광고 스크립트를 넣지 않는다.
- 자동 삭제는 앱 DB 기준이다. Convex의 서버 로그와 백업 보존은 별개다.
- Convex 서버는 국외에 있다. 실제 학생 운영 전에 학교의 개인정보 처리 기준(국외 처리 포함)을 확인한다. 이전 프로젝트의 개인정보 검토 문서를 참고한다.

## 10. 성공 기준

| 구분 | 기준 |
|---|---|
| 기술 | 학교 Wi-Fi에서 iPad 3~4대로 한 판을 오류 없이 끝낸다. 구경 화면의 획 지연이 1초 이내다 |
| 사용성 | 교사 설명 없이 1분 안에 첫 판을 시작한다. 한 판이 3~5분 안에 끝난다 |
| **놀이** | **① 한 판이 끝난 뒤 자발적으로 "한 번 더"를 한다**<br>② 이후 쉬는 시간에 교사가 권하지 않아도 학생들이 스스로 연다<br>③ 친구에게 불려 들어온 학생이 끝까지 남는다 |

### 실패했을 때 해석

| 관찰 | 해석과 다음 행동 |
|---|---|
| 첫 판에 반응이 없음 | 놀이 자체의 문제. 칸당 시간, 주제 카드, 덧그리기 모드를 다시 종이로 시험한다 |
| 첫 판은 웃었는데 다시 하지 않음 | 반복할 동기가 부족함. 투표, 아바타 같은 BACKLOG 항목을 검토한다 |
| 기다리는 학생이 딴짓을 함 | 칸당 시간을 줄이거나 구경 화면에 할 일을 더한다 |
| "수업 같다"는 반응 | 주제 카드를 더 엉뚱하게 바꾸고 단계 안내 문구를 놀이 말투로 바꾼다 |

## 11. 테스트 계획

| 단계 | 내용 | 통과 기준 |
|---|---|---|
| T0 | PC 브라우저 2~3개로 한 판 | 차례, 실시간 획, 공개가 정상 동작 |
| T1 | 방 만들기와 입장만 되는 버전을 학교 Wi-Fi + iPad 2대로 | 이 앱의 배포 주소가 학교망에서 열리고 실시간 갱신이 됨. 학교망에서 이미 Convex·Firebase 실시간 활동을 운영 중이라 위험은 낮다 |

## 12. 개발 순서

1. **M0** 프로젝트 세팅 (Vite + React + TS + Convex), Vercel 배포, GitHub 연결
2. **M1** 방 만들기, 입장, 대기실, 방장 → T1 학교망 확인
3. **M2** 차례와 서버 타이머 진행 (그림 없이 [완료]만)
4. **M3** 그림판, 획 저장, 실시간 구경
5. **M4** 공개 화면, 한 판 더, 교사 페이지 (목록과 이미지 저장)
6. **M5** 재접속, 자리 비움 처리, 로그, 24시간 삭제 → T2~T4
