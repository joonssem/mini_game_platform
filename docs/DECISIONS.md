# 결정 기록

중요한 기획과 기술 결정, 그리고 그 이유. 최신 결정이 위에 온다.

## 2026-10-07 · 게임 화면은 가로 전용, 한 화면에

- 결정: 그리기를 포함한 게임 화면은 가로 화면 전용. 세로로 들면 안내를 띄운다. 게임 중에는 스크롤 없이 한 화면에 들어가게 한다.
- 이유: iPad 9세대 Safari 확인(T1)에서 [완료] 버튼이 화면 밖으로 밀려났다. 교사가 그리기는 가로로만 진행하기로 정했다.
- 남은 과제: 그림판이 작아졌지만 그리는 데 큰 지장은 없음. 디자인을 새로 할 때 그림판을 더 키울 방법을 찾는다.

## 2026-10-07 · 이전 Convex + Vercel 프로젝트에서 배운 것 반영

근거: 이전 프로젝트 노트 (`private/reference/CONVEX_VERCEL_NOTES.md`, git 제외)

| 이전 프로젝트에서 겪은 문제 | 이 프로젝트에서 |
|---|---|
| Vercel Production과 Preview가 같은 Convex 개발 배포를 씀 | 로컬은 dev, Vercel Production은 prod. Preview는 쓰지 않는다 |
| 화면만 배포되고 서버 함수는 예전 그대로라 오류 | `npx convex deploy --cmd 'npm run build'`로 함께 배포 |
| 실제 수업에서 빈 참가자 자리가 입장을 막음 | 20초 이상 연결 없는 같은 번호 자리는 새 기기가 이어받음. 대기실 60초 제거 |
| `convex/tsconfig.json` 경로 별칭 때문에 배포 타입 검사 실패 | `convex/`는 상대 경로만 사용 |
| 학교 프록시 PC에서 Convex CLI 인증서 오류 | 검증을 끄지 않고 `NODE_OPTIONS=--use-system-ca` |
| 자동 삭제 범위를 과대 해석할 위험 | 앱 DB 삭제와 Convex 로그·백업 보존을 구분해 PRD에 명시 |

- 이전 프로젝트와 다르게 하는 것: `convex/_generated/`를 git에 **올린다**. 이전 프로젝트는 올리지 않고 `makeFunctionReference`로 참조를 따로 모았다. 이 프로젝트는 규모가 작으니 생성된 타입을 그대로 쓰는 쪽이 단순하고, 다른 AI 도구도 타입을 바로 볼 수 있다.
- 교사 비밀번호 변수 이름은 이전 프로젝트와 같은 `TEACHER_PASSCODE`로 맞춘다.
- 이전 프로젝트는 실제 학생 운영 전에 개인정보·국외 처리 확인을 별도 절차로 두었다. 이 프로젝트도 같은 확인이 필요하다.

## 2026-10-07 · 교사만 그림을 저장한다

- 결정: 교사 코드로 들어가는 `/teacher` 페이지에서 최근 24시간 안에 끝난 게임의 만화를 이미지로 저장한다. 교사 코드는 Convex 환경 변수에만 둔다.
- 이유: 교사가 관찰 기록과 학생 작품을 남길 수 있어야 한다. 학생 화면에 저장 버튼을 두면 그림이 학생 기기로 퍼지므로 두지 않는다.
- 24시간 자동 삭제는 그대로 둔다.

## 2026-10-07 · PRD 세부 규칙 확정

- 칸당 기본 45초 / 2명은 4칸을 각자 두 번씩 / 다시 하기 때 첫 순서가 한 칸씩 돌아감
- 앞 칸은 모두 보여 준다. 나중에 재미를 위해 바로 앞 칸만 보여 주는 방식을 실험한다.
- 학교망 실시간 연결: 학교망에서 이미 Convex·Firebase 실시간 활동을 운영 중이라 T1은 개발을 막는 단계가 아니라 확인 단계로 둔다.

## 2026-10-07 · 첫 게임은 A′ "한 장 만화 이어 그리기"

- 결정: 화면 하나를 차례로 넘기며 각자 다음 장면 한 칸을 그리고, 끝에 이야기 전체를 공개한다.
- 이유: 학생 선택에서 A(쉬움, 그리기를 좋아함)가 가장 많았고 B(완성된 만화를 함께 보는 재미)가 다음이었다. 국어 교과서의 이어 쓰기와 다음 장면 그리기 활동과 같은 구조라 익숙하다.
- 버린 대안: C 그림 전달(아무도 고르지 않음, 규칙이 복잡함). A 덧그리기와 B 동시 돌리기는 BACKLOG로 보낸다.

## 2026-10-07 · 단계 안내는 교과서 용어로

- 결정: 3명은 처음·가운데·끝, 2명과 4명은 발단·전개·절정·결말로 안내한다.
- 이유: 학생들이 이미 아는 용어이고, 빈 칸 앞에서 무엇을 그릴지 막히는 문제를 줄인다.

## 2026-10-07 · 남의 차례에는 획을 실시간으로 보여 준다

- 결정: 그리는 사람의 획을 선 하나 단위로 다른 기기에 보여 준다.
- 이유: 한 명씩 그리는 방식에서는 기다리는 시간이 곧 구경하는 시간이다. 구경이 재미있어야 기다리는 시간을 견딜 수 있다.
- 결과: 그림을 PNG 파일이 아니라 획 데이터로 저장한다. 실시간 구경과 공개 화면이 같은 데이터를 쓴다.

## 2026-10-07 · 기술 스택

- 이유: 여러 기기가 같은 게임 상태를 실시간으로 공유해야 한다. 정적 호스팅인 GitHub Pages만으로는 부족하다. 검색 노출과 서버 렌더링이 필요 없어서 Next.js 대신 Vite를 쓴다.
